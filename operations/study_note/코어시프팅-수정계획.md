# 코어 시프팅 코드 수정계획 (v1)

> 목표: conv2d의 코어 배치를 항상 (0,0)에서 시작하는 하드코딩을 풀어서,
> **임의 origin(시작 코어)에서 시작 + 임의 모양으로 코어 할당** 가능하게 만든다.
> → 모델 전체 실행 시 코어별 누적 부하를 분산(unfairness 완화), 성능 trade-off 측정.

---

## 0. 핵심 전략 (한 줄)

**"가상의 직사각형 배치는 그대로 두고, 실제 코어에 얹히는 origin(시작점)만 오프셋을 준다."**
- 코어 개수 계산·샤딩 로직은 이미 최적화됨 → **건드리지 않음 (존중)**
- 바꾸는 건 딱 하나: `{0,0}` 앵커 → `origin` 변수
- 커널 코드는 **거의 무변경** (좌표를 runtime arg로 이미 받음)

---

## 1. 확정된 수정 지점 (실측 라인)

### A. Sharded 팩토리 — `conv/conv2d/device/conv2d_op_sharded_program_factory.cpp`
| line | 현재 코드 | 역할 |
|---|---|---|
| **576** | `const CoreCoord top_left_core = {0, 0};` | **★ 최상위 앵커. 여기가 뿌리** |
| 577 | `top_left_core_plus_one = {1, 1};` | 앵커+1 (mcast receiver 시작 등) |
| 579-580 | `worker_core_from_logical_core(top_left_core)` | 논리→물리 좌표 변환 |
| 584 | `CoreRange(top_left_core, top_left_core)` | 단일코어(mcast 안함) 판정 |
| 600 | `CoreRange(top_left_core, CoreCoord(0, num_cores_y-1))` | HEIGHT: mcast sender 열(column) |
| 605 | `CoreRange(top_left_core, CoreCoord(num_cores_x-1, 0))` | mcast sender 행(row) |
| 607 | `CoreRange(CoreCoord(0,1), out_bottom_right_core)` | mcast receiver 범위 |
| 1070~1259 | `top_left_core_physical.x/y` 등 | **runtime arg로 커널에 전달** (이미 변수화됨) |

→ **576을 `origin`으로 바꾸고, 600/605/607의 하드코딩 `0`도 origin 기준으로 상대화**하면
   아래 1070~1259는 `top_left_core_physical`을 그대로 쓰므로 **자동 반영됨**.

### B. Width 팩토리 — `conv/conv2d/device/conv2d_op_width_sharded_program_factory.cpp`
| line | 현재 코드 | 역할 |
|---|---|---|
| **320** | `CoreCoord act_mcast_start_core_logical(0, 0);` | **★ activation mcast 시작 앵커** |
| 321 | (end는 `bounding_box()`로 동적 — 이미 유연) | mcast 끝점 |
| 322 | `worker_core_from_logical_core(...)` | 물리 변환 |

→ **320만 `origin`으로.** 끝점은 이미 bounding_box 기반이라 origin만 맞추면 됨.

### C. Halo 팩토리 — `sliding_window/halo/device/untilize_with_halo_program_factory.cpp`
⚠️ **정독 결과: (0,0) 하드코딩이 3곳. block이라도 자동 안전 아님.**
| line | 현재 코드 | 역할 |
|---|---|---|
| **554-561** | `core_id_to_noc_coords(0)` → `noc_TL` = `worker_from_logical(0,0)` | **mcast 좌상단 = 항상 (0,0). block 포함 전부.** ★가장 중요 |
| **586** | `CoreRange(CoreCoord(0,0), CoreCoord(rect_x-1, rect_y-1))` | 직사각형 코어셋 (HEIGHT/WIDTH만) |
| **689** | `cast_core = core_i == 0` | mcast 지휘 코어 = 첫 코어(index 0) |

- `all_cores`(line 88/409)는 shard_spec.grid에서 옴 → 코어 집합은 grid 따라감 (block: line 584)
- **근데 noc_TL/noc_BR 중 noc_TL은 (0,0) 고정** (noc_BR은 block에서 grid end 따라감, line 572-574) → **grid 옮기면 mcast 사각형 어긋남 = 버그**
- **∴ halo도 conv와 origin 동기화 필수.** 위 3곳(554-561/586/689) 다 origin 반영해야 함
- 당신 Stage 3 = block이라 코어는 따라가지만 **noc_TL/cast_core는 반드시 고쳐야** 정합성 유지

## 2. 수정 방식 (단계별)

### Step 1 — origin을 어디서 결정하나
현재 배치의 실제 코어셋은 `input_cores`(= `shard_spec().grid`)에 이미 들어있음.
- `origin = all_cores.bounding_box().start_coord;`
- 즉 **"내가 Python에서 지정한 grid의 좌상단"을 origin으로 자동 채택**
- 하드코딩 `{0,0}` 대신 이 값을 쓰면, grid를 어디에 잡든 그 위치에서 시작

### Step 2 — 앵커 치환 (sharded 예)
```cpp
// 576 (before)
const CoreCoord top_left_core = {0, 0};
// (after)
const CoreCoord top_left_core = all_cores.bounding_box().start_coord;  // origin
const CoreCoord top_left_core_plus_one =
    {top_left_core.x + 1, top_left_core.y + 1};
```
- 600/605의 `CoreCoord(0, num_cores_y-1)` → `CoreCoord(top_left_core.x, top_left_core.y + num_cores_y-1)` 식으로 **origin 상대 좌표로**
- 607 receiver도 `top_left_core_plus_one` 기준으로

### Step 3 — 커널은 무변경 (근거)
- 커널은 mcast 좌표를 `get_arg_val`(runtime arg)로 받음 (1070~1259에서 `top_left_core_physical`을 이미 넘김)
- host에서 origin 반영된 physical 좌표를 넘기면 → **커널 코드 수정 불필요**
- ⚠️ 단, 커널 내부에 `noc_x==0` 같은 절대좌표 가정이 없는지 1회 확인 필요

### Step 4 — halo origin 동기화
- conv에 넘긴 origin과 halo의 origin을 **같은 값으로** (line 586)
- 안 맞추면 halo 출력 코어 ≠ conv 입력 코어 → 데이터 불일치

### Step 5 — Python 제어점 (최상위)
- `models/.../ttnn_functional_resnet50.py`의 `create_sharded_memory_config_(grid, ...)`에서
  grid의 시작 좌표를 지정 → 이게 위 origin으로 흘러 내려감
- **가장 안전한 통제 지점**: op별로 grid 위치를 파이썬에서 바꿔가며 실험

## 3. 난이도 / 리스크

| 항목 | 난이도 | 리스크 |
|---|---|---|
| Width sharding (320) | 낮음 | 낮음 (앵커 1개, 끝점 이미 동적) |
| Height sharding (576, 1D) | 중간 | 중간 (mcast sender 열/행 상대화) |
| **Block sharding (2D)** | **높음** | **높음 (행·열 2축, receiver 사각형 재계산)** |
| Halo 동기화 (586) | 중간 | **높음 (틀리면 결과값 오류, 성능 아님)** |

**권장 순서: Width → Height → (검증 후) Block.**
Block은 2D라 마지막. 먼저 Width로 파이프라인(수정→빌드→측정) 전체를 한 번 돌려본다.

## 4. 실험 순서 (오늘 이후)

1. **Baseline 측정:** ResNet50 전체 실행 → Tracy(DeviceZoneScopedN)로 코어별 누적 활동
   - (이미 30배 spread 데이터 있음 → 재현/포맷 확정)
2. **최소 수정:** Width 팩토리 320만 origin으로 → 빌드 → 결과값 정합 확인(정확도)
3. **Shift 적용:** 몇 개 op의 grid origin을 Python에서 이동 → 재측정
4. **비교:** before/after 코어별 spread(불균형 지표) + end-to-end 성능(trade-off)
5. **확장:** Height, Block 순차 적용

**불균형 지표 후보:** max/min 비, 표준편차, Gini 계수 (누적 활동량 기준)
