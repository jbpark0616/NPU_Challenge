# conv 코어 시프팅 — 검증 실행 스펙 (Claude Code 실행용)

> **이 문서는 AI 코딩 에이전트가 읽고 실행하는 스펙이다.**
> 게이트 G0→G4를 **순서대로** 실행한다. **현재 게이트가 PASS하기 전에는 다음으로 넘어가지 않는다.**
> 게이트 실패 시: 즉시 중단 → 원인 보고 → 마지막 변경 롤백.

---

## 0. 에이전트 실행 규칙 (반드시 준수)

1. **한 번에 하나의 게이트만** 수행하고, 검증 통과를 확인한 뒤 다음으로 간다.
2. **conv 실행은 전부 컨테이너 안 + 보드에서** 이루어진다. `[CONTAINER]` 표시된 명령은
   `docker exec -it bos_host bash` 진입 후 실행한다. 로컬(호스트)에서 conv 실행 불가.
3. **C++ 파일을 수정하면 반드시 재빌드**한다 (§1의 빌드 명령). Python만 수정 시 재빌드 불필요.
4. 각 게이트는 **PASS 기준이 명시**돼 있다. 기준 미달이면 FAIL로 간주하고 중단·롤백·보고.
5. 코드 수정 전 반드시 해당 파일의 대상 라인 주변을 Read로 확인한다 (라인 번호는 이동했을 수 있음).
6. 절대 grid의 **모양(shape/aspect ratio)을 바꾸지 않는다.** origin(시작 좌표)만 이동한다.

---

## 1. 환경 / 빌드 / 실행 (전제조건)

- 코드 위치(컨테이너 내): tt-metal 소스 트리. 이 저장소의 `operations/`는 컨테이너 코드의 복사본이다.
  **실제 수정·빌드는 컨테이너 안의 원본 트리에서** 한다.
- 컨테이너 진입: `docker exec -it bos_host bash`
- 빌드 (C++ 변경 후): `[CONTAINER]` tt-metal 표준 빌드 명령 (예: `./build_metal.sh` 또는 프로젝트 지정 명령).
  ※ 정확한 빌드 명령은 컨테이너의 기존 빌드 스크립트를 따른다.
- 테스트 실행: `[CONTAINER] python conv_test.py`

---

## 2. 핵심 원칙 (검증 판정의 근거)

**시프팅 = 같은 연산을 다른 코어에서 수행. 출력 수치는 불변이어야 한다.**

- **정합성 (correctness):** 시프팅 후 conv 출력 == 시프팅 전(golden) 출력.
  판정: `PCC(out, golden) >= 0.9999` (가능하면 bit-exact).
- **배치 이동 (placement moved):** conv가 실제로 shifted 코어에서 실행됐다.
  판정: `out.memory_config().shard_spec().grid` 의 bounding_box start != baseline start.
- **두 조건 동시 만족 = 시프팅 성공.** 하나라도 실패 = FAIL.

## 3. 용어 정의

- **origin** := `all_cores.bounding_box().start_coord`
  (해당 텐서 shard_spec의 실제 grid 좌상단. baseline에서는 (0,0).)
- **리팩터(refactor)**: 하드코딩 `{0,0}`을 `origin`(= bounding_box().start_coord)으로 교체.
  baseline grid가 (0,0)에 있으므로 **교체 직후 origin==(0,0) → 동작 불변**이어야 한다.
- **플립(flip)**: Python shard_spec grid의 시작 좌표를 shifted 값으로 변경.
  → 리팩터된 컴포넌트들이 bounding_box를 통해 **자동으로 함께 이동**.

## 4. 테스트 하니스 스펙 — `conv_test.py` (에이전트가 생성)

**요구 동작:**
1. 고정 seed로 입력 x, 가중치 w 생성 (torch).
2. **torch 골든**: `torch.nn.functional.conv2d(x,w,...)` (sanity용).
3. **ttnn 실행**: 입력을 샤딩 memory_config로 device에 올리고 `ttnn.conv2d(...)` 실행.
   - conv_config / memory_config는 `ttnn_functional_resnet50.py`의 해당 stage 설정을 **그대로 복사**해 사용한다 (API 사용법의 정답 소스).
   - `origin` 인자를 받아 shifted 배치도 실행 가능해야 한다.
4. **출력 회수 + 배치**: `out = ttnn.to_torch(tt_out)`, `grid = tt_out.memory_config().shard_spec().grid`.
5. **비교 함수**: tt-metal 표준 `comp_pcc` 사용. `assert pcc >= 0.9999`.
6. **golden 저장/로드**: baseline 출력을 `golden/<case>.pt`로 저장, 이후 로드해 비교.

**테스트 케이스 (resnet50.py에서 추출 → `conv_configs.py`):**
| ID | 샤딩 | factory | 비고 |
|---|---|---|---|
| T1 | HEIGHT | sharded | halo 경유 |
| T2 | BLOCK | sharded | ★주 타깃 (Stage3) |
| T3 | WIDTH | width | |
| T4 | 1×1 | matmul | matmul 경로 확인 |

**halo 단독 검증용:** `ttnn.halo(...)`를 conv 없이 단독 호출해 halo 출력을 별도로 비교할 수 있어야 한다 (G2에서 사용).

## 5. 게이트 시퀀스 (G0 → G4, 순서 엄수)

### G0 — Baseline golden 캡처
- **작업:** `conv_test.py`, `conv_configs.py` 생성. 코드 **수정 없이** baseline 실행.
- **[CONTAINER]** `python conv_test.py --capture-golden`
- **PASS 기준:**
  - 각 케이스 T1~T4에서 `PCC(ttnn_out, torch_golden) >= 0.99` (하니스 자체가 올바름)
  - `golden/T1..T4.pt` 및 baseline `grid` 저장됨
- **FAIL 시:** 하니스/설정 오류. C++ 수정 착수 금지. 원인 수정 후 재실행.

### G1 — Sharded factory mcast 리팩터 (동작 불변)
- **작업:** H-mcast, H-mcast2, H-mcast3 (§3.1)를 `origin = all_cores.bounding_box().start_coord` 기반으로 교체.
  **값은 여전히 (0,0)이어야 함** (baseline grid가 (0,0)이므로).
- **[CONTAINER]** 재빌드 → `python conv_test.py --cases T1,T2`
- **PASS 기준:** `PCC(out, golden) >= 0.9999` (출력 불변). grid 불변.
- **추가 검증:** factory에 임시 `log_info("mcast top_left = {}", top_left_core);` 삽입해 **(0,0) 출력 확인**.
- **FAIL 시:** 리팩터가 math를 깨뜨림 → 롤백, 상대좌표 수식(600/605/607) 재검토.

### G2 — Halo 리팩터 (동작 불변) + halo 단독 검증
- **작업:** HALO-tl, HALO-rect, HALO-cast (§3.1)를 origin 기반으로 교체. 값은 (0,0) 유지.
- **[CONTAINER]** 재빌드 → `python conv_test.py --halo-only --cases T1,T2`
- **PASS 기준:** **halo 단독 출력** `PCC(halo_out, halo_golden) >= 0.9999`. 이어서 conv 출력도 golden과 동일.
- **FAIL 시:** halo 배선 문제 국소화됨 → 롤백, 554-561/586/689 재검토.

### G3 — Width factory + grid 생성 리팩터 (동작 불변)
- **작업:** W-mcast(320) origin화. `conv2d_utils.cpp` num_cores_to_corerangeset를 start_core 버전(work_split.cpp line 77)으로 (값 (0,0) 유지).
- **[CONTAINER]** 재빌드 → `python conv_test.py --cases T1,T2,T3`
- **PASS 기준:** 전 케이스 `PCC >= 0.9999`, grid 불변.
- **FAIL 시:** 롤백, 해당 변경 재검토.

### G4 — 플립 (실제 시프팅, 원자적) + 최종 검증
- **작업:** PY-grid(557)를 shifted origin (예: `(1,0)`)으로 변경. (C++는 이미 bounding_box 기반이라 자동 추종.)
- **[CONTAINER]** (Python만이면 재빌드 불필요) → `python conv_test.py --origin 1,0 --cases T1,T2,T3`
- **PASS 기준 (둘 다):**
  1. `PCC(out, golden) >= 0.9999` (수치 불변)
  2. `out.grid` bounding_box start == (1,0) 이고 baseline과 다름 (배치 이동)
  3. (권장) Tracy로 실제 활동 코어가 이동했는지 확인
- **FAIL 시:**
  - 출력 깨짐 → origin 동기화 누락 (halo/mcast/grid 중 하나가 안 따라옴). §3.1 전 항목 재확인.
  - grid 안 움직임 → PY-grid 변경이 전파 안 됨. shard_or_reshard 경로 확인.

### G5 — Matmul 이식 (1×1 경로, 선택/후속)
- **작업:** MM-1d/2d (§3.1)에 G1과 동일 패턴 적용. `grep`으로 (0,0)/top_left 위치 확정 후 origin화.
- **검증:** T4로 G1~G4와 동일 절차.

## 6. 롤백 / 안전 규칙

- 각 게이트는 **독립 커밋**으로 관리 (git). FAIL 시 `git checkout -- <file>`로 즉시 롤백.
- **모양 변경 금지**: origin(시작좌표)만. aspect ratio·코어 개수는 건드리지 않는다.
- **wrap(경계 넘는 배치) 금지**: 이번 스코프 아님. origin+shape가 20코어 범위(sx0-4 × sy{0,1,2,4})를 벗어나면 안 됨.
- 커널 파일은 수정하지 않는다 (좌표는 runtime arg로 전달됨). 단 커널에 절대좌표 가정이 없는지
  `grep -rn "== 0" kernels/`로 확인만 한다.
- 각 게이트 통과 시 `conv실행흐름-수정체크리스트.md`의 해당 체크박스를 체크한다.

## 7. 실행 요약 (에이전트용 한눈에)

```
G0 골든 캡처        → PCC(ttnn,torch)≥0.99, golden 저장
G1 sharded mcast    → 리팩터(값0,0) → PCC(out,golden)≥0.9999
G2 halo             → 리팩터(값0,0) → halo단독 PCC≥0.9999 + conv PCC≥0.9999
G3 width+grid       → 리팩터(값0,0) → PCC≥0.9999
G4 플립(Python 557) → origin=(1,0) → PCC≥0.9999 AND grid 이동
G5 matmul 이식      → T4로 동일 절차
```
**불변식: 출력은 항상 golden과 동일(PCC≥0.9999). G4에서만 배치가 이동한다.**
